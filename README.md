# QR BEFORE — 주차장 QR, 열기 전에 확인하세요

주차장 정산기나 안내판의 QR을 열기 전에 주소의 위험 신호를 검사하고, 공공데이터에 등록된 주차장 관리기관과 대조해 알려 주는 큐싱(QR 피싱) 예방 웹서비스입니다.

- 팀: 강경파 (강혜성, 김경민)
- 대회: 공공데이터 AI 해커톤
- 서비스 주소: (배포 후 기입)
- 시연 지역: 대전 서구 둔산동 갤러리아타임월드 주변

## 왜 만들었나

주차 요금을 QR로 내는 운전자는 그 QR이 관리기관의 것인지 확인할 방법이 없습니다. 누군가 정산기에 가짜 QR 스티커를 덧붙이면, 찍는 순간 가짜 결제 페이지가 열리고 카드 정보를 입력하게 됩니다. 휴대폰 카메라는 주소를 읽어 열어 줄 뿐이고, `se0gu.com`처럼 한 글자만 바꾼 주소는 눈으로 가려내기 어렵습니다.

실제로 이런 일이 일어나고 있습니다.

| 시기 | 장소 | 내용 | 출처 |
|---|---|---|---|
| 2026년 8월 | 캐나다 뉴웨스트민스터 | 주차 미터기 곳곳에 가짜 QR 스티커. 피해 신고가 잇따랐고 한 명은 2,000달러를 잃음 | [뉴웨스트민스터 경찰](https://www.nwpolice.org/news-media/media-releases/police-warn-of-fraudulent-qr-codes-on-parking-meters/) |
| 2026년 4월 | 영국 칼라일 | 공영주차장 세 곳에서 악성 결제 사이트로 연결되는 가짜 QR 발견 | [컴벌랜드 의회](https://www.cumberland.gov.uk/news/2026/car-park-customers-urged-be-vigilant-fake-qr-codes-placed-carlisle) |
| 2024년 10월 | 국내 | 과기정통부·경찰청·KISA 등 6개 기관 합동 경고. 공유 킥보드 정상 QR 위에 가짜 QR을 덧붙인 수법 확인 | [뉴시스](https://mobile.newsis.com/view/NISX20241023_0002931067) |

두 해외 기관 모두 "원래 QR을 쓰지 않으니 관리기관에 직접 확인하라"고 안내했습니다. QR BEFORE는 그 확인 경로를 현장에서 바로 보여 줍니다.

## 어떻게 동작하나

1. 주차장 이름을 검색하거나 가까운 순으로 지금 있는 주차장을 고릅니다.
2. QR을 카메라로 찍거나 사진을 올리거나 주소를 붙여 넣습니다. 앱은 주소를 읽기만 하고 열지 않습니다.
3. 보안 엔진이 주소를 검사하고 관리기관의 참고 도메인과 대조합니다.
4. 결과와 이유, 관리기관 연락처를 보고 결제할지 정합니다.

결과는 세 가지입니다. "안전합니다"라는 말은 쓰지 않습니다.

| 결과 | 뜻 | 예시 |
|---|---|---|
| 참고 목록과 일치 | 관리기관 공식 도메인과 같음. 결제 페이지가 진짜라는 보장은 아님 | `https://parking.seogu.go.kr/pay` |
| 의심 징후 발견 | 위험 신호가 하나 이상 있음 | `https://se0gu.com/pay` (숫자 0) |
| 확인 불가 | 참고 목록에 없어 판단할 근거가 없음. 관리기관 연락처로 확인 안내 | `https://example-pay.co.kr/p/123` |

## 보안 검사 항목

모든 판단은 브라우저의 URL 파서가 뽑은 실제 접속 도메인(hostname) 기준입니다. 검사하는 동안 그 주소에 접속하지 않습니다.

의심으로 판정하는 강한 신호

- 위험한 주소 형식: `javascript:`, `data:`, `vbscript:`, `file:` 등 (공백·탭을 섞어 숨겨도 탐지)
- @ 속임수: `https://seogu.go.kr@evil.com` 은 실제로 `evil.com` 에 접속
- IP 주소 직접 접속: `https://192.168.0.10`, 정수로 숨긴 `http://3232235530` 포함
- 암호화되지 않은 `http`
- 공식 도메인을 주소 안에 끼워 넣기: `seogu.go.kr.pay-check.com`
- 철자 흉내: 숫자 0↔o, rn↔m 같은 헷갈리는 글자, 한 글자 추가·누락, 이웃 글자 순서 바꿈, 하이픈 끼워 넣기
- 다른 나라 문자로 흉내 낸 도메인: 키릴 문자 `е`, `о`를 섞은 `sеоgu.go.kr` (퓨니코드 직접 해독)

이유에만 적고 판정은 바꾸지 않는 약한 신호

- 단축 주소(bit.ly, han.gl 등): 목적지를 열기 전엔 알 수 없음
- 비표준 포트, 지나치게 깊은 하위 도메인, 한글 등 국제화 도메인
- 기관 이름(지명)이 들어간 다른 도메인: `daejeon-tour.co.kr` 같은 정상 사이트가 많아 의심으로 올리지 않음
- 다른 관리기관의 공식 도메인: 화면에서 주황색으로 따로 표시

정상 주소를 의심으로 잘못 찍지 않도록 강한 신호만 판정에 반영했습니다. 정상 결제대행사, 포털, 다른 지역 구청, `dongbu.co.kr` 같은 비슷한 일반 단어가 의심으로 나오지 않는지도 검사에 넣었습니다.

## 사용한 공공데이터

| 데이터 | 제공 | 쓰는 곳 |
|---|---|---|
| [전국주차장정보표준데이터](https://www.data.go.kr/data/15012896/standard.do) | 국토교통부(소관)·지방자치단체(제공) | 주차장 검색, 거리순 정렬, 관리기관·전화번호·자료 기준일 안내 |

전국 18,939건 중 대전광역시 562곳을 추렸습니다(`scripts/build_parking_data.py`). 원본에는 결제 도메인 열이 없어서, 대전 관리기관 6곳(대전시, 서구·중구·유성구·동구청)의 공식 홈페이지에 직접 접속해 도메인을 확인하고 `data/trusted-domains.json`에 출처와 확인 날짜를 함께 적었습니다. 이 목록은 "참고 도메인"으로만 씁니다.

한국환경공단 전기자동차 충전소 정보 API도 활용 승인을 받아 두었습니다. 충전기 QR로 넓힐 때 씁니다.

## 검사 결과

`npm test`로 42건을 검사했고 모두 통과했습니다.

- URL 사례 32건: 참고 목록과 일치 5건, 의심 징후 발견 13건, 확인 불가 14건 (정상 사이트 오탐 검사 포함)
- 구조·안전 검사 10건: 출력 규격, 잘못된 입력 처리, 검사 중 네트워크 접속 없음 등

사례별 결과와 이유는 [docs/test-results.md](docs/test-results.md)에 있습니다.

## 실행 방법

정적 파일만으로 동작하며 서버나 API 키가 필요 없습니다. 데이터를 `fetch`로 읽기 때문에 `file://`로 열지 말고 로컬 서버로 여세요.

```bash
npx serve .        # 또는 python3 -m http.server
npm test           # 보안 엔진 검사 (Node.js 18 이상)
node scripts/make-test-report.js   # 결과표 다시 만들기
```

카메라 QR 스캔은 https 주소(배포 사이트)에서만 동작합니다.

## 한계

- 참고 도메인과 일치해도 결제 페이지가 진짜라는 보장은 아닙니다. 그래서 "안전" 대신 "참고 목록과 일치"라고 표시합니다.
- 관리기관이 외부 결제대행사 주소를 쓰는 경우 "확인 불가"로 나옵니다. 이때는 화면의 관리기관 전화번호로 확인하도록 안내합니다.
- 참고 도메인은 지금 대전 6개 기관만 확인했습니다. 지역을 넓히려면 기관별 도메인 확인이 더 필요합니다.
- 단축 주소의 실제 목적지는 열지 않고는 알 수 없어 "확인 불가"로 둡니다.

## AI 활용

QR 판정에는 AI를 쓰지 않습니다. 같은 QR에는 늘 같은 결과가 나와야 하고, 판정 이유를 설명할 수 있어야 하며, 이용자가 찍은 주소를 외부 AI 서버로 보내지 않기 위해서입니다.

AI는 만드는 과정을 나눠 맡았습니다. Claude는 공공데이터 정제, 보안 검사 규칙과 테스트 작성, 오탐 사례를 찾아 규칙을 고치는 일, 큐싱 사례와 기관 도메인 조사를 맡았고, Codex는 웹 화면과 QR 인식 구현을 맡았습니다. AI가 찾은 출처와 도메인은 사람이 직접 열어 확인한 것만 넣었습니다.
